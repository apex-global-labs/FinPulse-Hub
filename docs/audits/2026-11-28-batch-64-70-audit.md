## Findings — release blockers
1. Structural catalogue tests pass, but an independent placeholder comparison found 18 token mismatches: `{field}` was added to source error messages that do not contain that token for `prime-checker` (`invalid-integer`), `prime-factorization` (`invalid-integer`) and `circle` (`invalid-number`), across six locales.
2. Numeric-limit wording is incomplete: the `prime-checker` and `prime-factorization` range recovery text must preserve the source ceiling of 1,000,000,000,000. Safe-integer validation guidance should also be retained.
3. Several FAQ answers were generic rather than tool-specific. Zero-input behavior and decimal acceptance differ across these tools; they need accurate, per-tool answers before approval.
4. Browser direction and accessibility-label assertions passed for the six translated locales. However, a dedicated axe/WCAG scan of these seven math tools was not run. Lighthouse accessibility scores were measured on the homepage and the existing hydration-log-tracker route, not these seven math routes. Do not treat these results as WCAG certification for #64–70.
