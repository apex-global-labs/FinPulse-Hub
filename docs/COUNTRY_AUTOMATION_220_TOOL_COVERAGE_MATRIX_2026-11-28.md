## Executive result

- Canonical inventory: **220 tools / 220 unique stable IDs**, distributed across 10 source modules. All 220 IDs were cross-checked against the 220 stable IDs in main's `docs/FINANCE_TOOL_MASTER_REGISTRY.md`; there were no missing or extra IDs.
- Overall country-context classification: **0 Complete, 49 Partial, 2 Missing, 169 Not Applicable**.
- Country relevance: `Currency / monetary display`: 38; `Country tax / jurisdiction`: 11; `Regional workweek / public holidays`: 2; `Not Applicable`: 169.
- The site has a global Country/Region selector and a static 249-country/territory → 154-currency registry. **Selecting a country does not automatically apply its currency or load a calculator's jurisdiction dataset.** Currency preference is a separate setting; the UI has an explicit “Use suggested currency” action.
- Currency presentation is already connected to **37 Finance tools + 5 additional monetary tools**. This is display/interpretation context, not FX conversion and not country-triggered.
- Country-specific tax presets/profiles exist, but most require the user to select a separate preset/profile. They are not driven by the global country selector.
- The seven-language candidate has a tool-content runtime, but it activates only `approved`/`published` records. At this inspected PR #73 head, all 1320 target-locale cells are Draft or Not Started; **0 approved/published**. English remains the live source fallback.
- No item is classified Complete for the requested end-to-end country-selection automation, because the global country selector is not wired to each applicable calculator's data selection.

## Classification rules

- **Complete:** country selection automatically loads verified applicable data, with an explicit manual fallback and provenance. No tool met this bar.
- **Partial:** a separate currency preference, tool-specific country preset, or tax-profile selector exists, and/or manual values are supported, but the global country selector does not drive it or coverage is incomplete.
- **Missing:** a regional setting is relevant but the tool does not consume global country/measurement context; user manually chooses time zones/units.
- **Not Applicable:** no country-specific dataset is required for the tool's calculation. This does not mean the tool is incomplete.
- Locale codes in the last column are ordered `hi/ar/ur/zh-CN/ja/ru`: **D** = draft; **N** = not-started; **A** = approved/published. English is the source locale for all 220 tools. The six target locales have the same status for each tool at this candidate head; status is read from the full 3,053,699-character `translations/tool-content.json` blob, not inferred from titles.

## Runtime and data findings

### Global Country / Currency / Locale context
- `global-context.js` contains 249 country/territory rows and 154 currency codes.
- Country selection updates `countryCode`; `useSuggestedCurrency()` is a separate explicit action. There is no country-change auto-apply.
- `index.html` exposes Country/Region, Language/Locale and Preferred Currency selectors. The note explicitly says they are independent and changing currency does not convert existing numbers.
- `app.js` connects the global currency preference to 37 Finance tools and 5 Lifestyle tools. It does not connect `countryCode` to those tools' tax or country presets.
- The measurement-system value exists in the context API but is not exposed as a selector in the current header and is not used to preselect unit-converter fields.

### Country-specific finance data
- `tax-data.js`: 23 profiles (4 US federal filing statuses, 2 UK profiles, 13 Canada province/territory profiles including Québec, 4 Bangladesh taxpayer categories); `checkedOn: 2026-11-18`; sources are recorded by jurisdiction family. `income-tax` and `salary` load a profile only after manual selection in a separate Country/region and tax-year dropdown.
- `smart-ui.js`: Sales Tax and VAT/GST have country/region preset dropdowns; Inflation has four country estimates plus a custom option. These are manually selected, not auto-selected from global country. Preset metadata uses `checkedOn: 2026-11-18` and includes source URLs/notes.
- Sales Tax US preset is explicitly a placeholder requiring local state/city rate; zero must not be treated as a tax-free claim. Canada presets are starting-point combined rates; exemptions and place-of-supply rules remain out of scope.
- `tax-state-data.js` on main contains 50 state rows and a default `statewisenews.com` source with `checkedOn: 2026-11-18`; 47/50 entries use that default source and only 3 entries override it. This is not equivalent to per-state official verification. PR #74's unmerged candidate documents a stricter boundary (8/50 no-income-tax states verified for automatic zero; 0/50 positive-rate schedules fully verified; unsupported states remain manual-only). **That PR #74 safeguard is not active on main.**
- Generic Tax, Paycheck, Payroll and Tax Refund tools accept user-entered figures/rates/withholding; these are manual calculations, not country-specific tax engines. 401(k) and IRA remain US-specific and USD-denominated; contribution/eligibility limits are not enforced.

### Currency behavior and fallback
- 37 Finance + 5 Lifestyle tools follow the global preferred currency for display. Changing it does not convert or rewrite numeric inputs.
- 401(k)/IRA remain USD; Income Tax/Salary use the selected tax-profile currency; Currency Converter and transfer tools retain explicit source/destination currencies.
- Currency Converter uses Frankfurter published reference rates where supported and has an explicit manual-rate fallback. Unsupported pairs do not become verified rates.
- Country → suggested currency remains an explicit user action, not an automatic country-data load.

### Seven-language status
- Main branch currently exposes locale preference/document `lang` and `dir`, but its live page states that translated tool content is not enabled.
- PR #73 candidate adds `translation-engine.js` and `tool-content-runtime.js`. The tool runtime only localizes a tool when its locale record is approved/published and all required fields are complete; otherwise it returns the English source.
- Full candidate blob status: 46 Draft and 174 Not Started per locale; 0 approved/published per locale (1,320 target-locale cells total). Draft is not release-ready and is not activated.

## Highest-priority gaps (audit findings only; no fixes applied)

1. **P1 — Country selector is disconnected from calculator data.** Keep the current explicit currency-apply action unless/until country selection is safely mapped to the appropriate tool and verified data source. A country choice must not silently overwrite a user's manually selected currency.
2. **P1 — Tax profiles are manually selected and geographically incomplete.** Add country-profile coverage only from verified official sources; preserve manual input fallback when no verified profile exists.
3. **P1 — US state tax provenance on main is weak.** Main's 50-state dataset uses a broad third-party source by default. PR #74 contains stricter verification/manual-only controls, but it is an unmerged candidate and cannot be counted as production behavior.
4. **P2 — Sales/VAT/Inflation presets are manually chosen.** Global country selection does not select them; custom/manual rates exist and must remain available.
5. **P2 — Business Days and Working Days lack country holiday calendars.** Both accept a manual holiday list and workweek pattern. Time-zone tools remain Not Applicable because a country can contain multiple IANA zones; users correctly select the exact zone. Unit converters are also Not Applicable because the conversion is country-independent and users select explicit units.
6. **Not Applicable — Unit conversion.** All 20 unit-converter tools use explicit source/target units; country selection does not change conversion factors. A country-based default could be a later convenience, not a required country-data dependency.
7. **P1 — Seven-language tool content is not active.** PR #73 has 46 Draft + 174 Not Started records per locale; runtime fallback correctly remains English because no records are approved/published.

## Recommended next implementation sequence (after this matrix is reviewed)

1. Reconcile Country Registry ↔ global settings ↔ Currency Integration without introducing another registry or engine.
2. Connect only existing verified tax/VAT/Inflation profiles to the global country choice, with explicit handling for multi-jurisdiction countries and manual override.
3. Make unsupported/unverified jurisdictions stay manual-only; do not infer rates from country names or neighboring jurisdictions.
4. Add country-aware time-zone/holiday/measurement defaults only where official/maintained data is available; preserve manual selectors.
5. Continue PR #73 translation batches independently; no tool locale becomes active until all schema fields, tokens, formula/numeric invariants and linguistic/domain review gates pass.
